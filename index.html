HTML Images

Notes on putting pictures on a web page: the <img> element, file formats, and accessibility.

The img element Formats Accessibility Checklist

1. The <img> element

Images are not drawn in HTML. You point to a file with src, and you describe that file with alt. In this demo every picture lives in the img/ folder. 

<img
  src="img/campus-photo.jpg"
  alt="Three students with backpacks walking down a campus path between red brick buildings."
  width="1280"
  height="720"
/>
  • src — the path to the file. Use a folder such as img/ so HTML and pictures stay organized.
  • alt — the text equivalent. Screen readers read this. If the image fails to load, browsers show this text instead.
  • width and height — the real pixel size of the file. The browser can reserve space before the file arrives, which stops the page from jumping.

CSS then scales the image to fit the layout (max-width: 100% and height: auto). You still write the real width and height in HTML.

2. Image formats

The file extension tells the browser how to decode the picture. Choose the format that matches the kind of image.

GIF — animation

GIF is an older format with a small colour palette. Use it for simple animations. Prefer PNG or WebP for still graphics.

PNG — sharp graphics and transparency

PNG is lossless. Edges stay sharp, so it suits logos, icons, and screenshots. It can also leave pixels fully see-through.

JPG — photographs

JPG (JPEG) uses lossy compression. It is the usual choice for photos: many colours, gradients, and no need for transparency.

WebP — modern and smaller

WebP is a newer format. It can be lossy or lossless, can include transparency, and is often smaller than JPG or PNG at similar quality. Current browsers support it.

When to pick which format

Quick guide to GIF, PNG, JPG, and WebP
Format Best for Transparency Animation Compression
GIF Simple looping animations Yes (1-bit) Yes Limited colours (256)
PNG Logos, icons, screenshots Yes No Lossless
JPG Photographs No No Lossy
WebP Photos or graphics on the modern web Yes Yes Lossy or lossless

3. Accessibility guidelines

WCAG success criterion 1.1.1 Non-text Content says every image needs a text alternative. The alt attribute is how HTML does that. Write alt for the purpose of the image, not a dump of every visual detail.

Informative images need a real description

If the picture teaches, identifies, or adds meaning, describe that meaning. Do not start with “image of” or “picture of”: the screen reader already announces that it is an image.

Avoid

alt="image of banana.gif"
alt="picture of a campus"

Prefer

alt="Cartoon yellow banana dancing with pom-poms."
alt="Three students walking down a campus path between brick buildings."

Decorative images use empty alt

If the image is only decoration and adds no information, use alt="". Leave the attribute in. A missing alt is an error; an empty alt tells assistive technology to skip the image.

<img src="img/decorative-dots.png" alt="" width="120" height="24" />

<figure> and <figcaption>

A visible caption is extra context for everyone. It does not replace alt. Screen reader users still need the alternative text, and sighted users still need the caption under the picture.

Linked images describe the destination

When an image is the only content inside a link, the alt text is the link name. Describe where the link goes, not the drawing of the icon. 

<a href="#checklist">
  <img src="img/it-logo.png" alt="Go to the accessibility checklist" />
</a>

Complex images need a short alt plus nearby text

Charts and diagrams cannot fit all of their data into a short alt. Give a one-sentence summary in alt, and put the full meaning in the page next to the image. aria-describedby points assistive technology at that longer text.

Enrollment grows each year. Year 1 is the shortest bar, Year 2 is about twice as tall, and Year 3 is the tallest — a little over three times Year 1. Colour is extra decoration; the heights already carry the meaning, so the information does not rely on colour alone.

Do not rely on images of text

If the words matter, put them in HTML. Pictures of text cannot be resized cleanly, cannot be translated, and are easy to miss in alt. Logos are a common exception; then the alt should contain the same words as the logo.

Common mistakes

  • No alt attribute. Screen readers may read the file name instead. Always include alt, even when it is empty.
  • File name as alt. alt="campus-photo.jpg" is not a description.
  • Repeating “image of”. Assistive technology already says it is an image.
  • Alt that copies the caption word for word. Give each one a job: alt replaces the picture; figcaption comments on it.
  • Information only in the picture. If a user cannot see the image, they must still get the same information from text.

4. Checklist

  1. Keep every image file in img/.
  2. Pick GIF for simple animation, PNG for logos and transparency, JPG for photos, WebP when you want a smaller modern file.
  3. Every <img> has an alt attribute.
  4. Informative images get a short, useful description.
  5. Decorative images get alt="".
  6. Linked images describe the destination, not the artwork.
  7. Charts get a short alt plus a text explanation on the page.
  8. Set width and height to the real pixel size of the file.
